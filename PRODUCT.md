# Product

## Register

brand

## Users

The primary audience is hiring managers, security engineering teams, and technical collaborators evaluating Alexander Biddle's cybersecurity range. Visitors need to understand the work quickly, scan representative project scopes, and see a credible connection between offensive thinking, defensive engineering, analyst reporting, and software development.

## Product Purpose

BiddleSec is a cybersecurity engineering portfolio. It positions Alexander as a practical security professional who can map risk, validate findings, communicate evidence, and build software that helps teams act on security work. Success means visitors can identify the professional focus within the first viewport and reach relevant project or contact information without friction.

## Brand Personality

Disciplined, investigative, electric.

The site should feel like a live security operations surface with a deliberate cyberpunk edge. It must communicate control and technical depth, not theatrical hacking imagery.

## Anti-references

- Generic hacker-movie interfaces with a green wash over every surface.
- Multicolor neon nightclub palettes that compete with the content.
- Generic AI SaaS glassmorphism, soft gradient blobs, and repeated feature-card templates.
- Editorial magazine styling that distracts from the security engineering focus.
- Dense terminal cosplay that makes the portfolio harder to scan.

## Design Principles

1. **Signal, not wash.** Green is a meaningful illumination layer for status, interaction, and hierarchy. It must not tint the entire interface.
2. **Evidence over spectacle.** Atmospheric effects support the security narrative, while project scope and readable content remain primary.
3. **Operational clarity.** Visitors should scan the site like a well-structured security report: identity, capability, evidence, outcome, contact.
4. **Range with one voice.** Offensive security, defensive engineering, analysis, and frontend development belong to one coherent professional profile.
5. **Motion with restraint.** Reactive canvases can add depth, but controls and content remain stable and reduced-motion users receive a complete experience.

## Accessibility & Inclusion

Target WCAG 2.2 AA contrast for text and interactive controls. Preserve visible keyboard focus states, semantic navigation, readable body line lengths, and large touch targets. Never rely on color alone to communicate state. Respect `prefers-reduced-motion` across CSS animations and canvas renderers.
